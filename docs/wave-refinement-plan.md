## 1. Ontological Foundations: Event-Driven On-Demand Bot Dispatching & the Artificial Brain

> **Core Idea:** What are called agents or bots are one base model wearing different masks (`Bot = base model + charter + skills`). Nothing is really created or retired; the model switches context according to the task at hand. "Creating" a bot means loading a charter and its skills into a fresh context; "retiring" it means dropping that context. Because each task loads only the context best suited to it—and discards that context once the finished artifact is handed over—there is no need for long contexts, and standing-agent defects (**long-context drift**, **stale memory**, and **role bleed**) are eliminated at the root. *(Note: On 2026-11-09, cold critic roles [`Critic`, `Stylist`, `Evaluator`, `recap-critic`] were retired from the workflow so that each stage runs as a clean single-purpose Maker context verified by deterministic scripts and `sha256` handoffs.)*

Designing an agentic authoring, memory-consolidation, or engineering-planning pipeline by asking a standing agent session to draft, research, translate, and publish within one uninterrupted token trajectory pits the structural mechanics of autoregressive models against the structural mechanics of human cognition. Traced from the single premise of `/ontological-clarity` (*self-distinguishing activity occurs — uncaused, unceasing*), the system is wired around six runtime-agnostic invariants:

### 1.0 Central Principle: Delegate Tasks, Never Decisions (Zero Watchdogs or Deadline Rules)
- **Only tasks can be delegated, never decisions.** Decisions are always made by the living Mind; so-called automated decisions are pre-made decisions being executed. Bots carry out tasks (drafting an essay, translating it, scouting external constraints, recomputing a hash, handing over a finished file). Choosing between unranked premises, or deciding what to do with a non-trivial stall, a crash, or a hash mismatch, are decisions. Decisions stay with the Human Operator.
- **Irreducible premise decisions, stalls, crashes, and hash mismatches go to the human.** When an open question cannot be derived from `/ontological-clarity` and existing repository premises (after running a cold, retiring `Scouter` if external prior art applies), the tension is stated briefly (`HOLD`) and the run waits for the human to decide. When a step crashes or stalls, if the trace confirms a deterministic local fix (such as killing a confirmed-stuck read-only TUI process), the agent executes and reports it; if a genuine premise decision remains, it goes to the human (always re-running any redone step in a **fresh context**, never by patching or restarting the old context).
- **No rule or watchdog stands in for judgment.** A deadline rule (*"if no answer by morning, publish anyway"*) or a watchdog (*"if a step is silent for an hour, restart it"*) looks like an automated decision, but is actually a decision made earlier without knowledge of the situation and executed blindly later. The scheme uses neither.
- **One Single House Rule:** The entire scheme rests on one house rule, the `/ontological-clarity` skill, loaded by every bot by reference and never restated. Settling a point by tracing it back to the shared premise executes the pre-made house rule the human chose; any point that cannot be traced to the shared premise requires a new decision and goes to the human.

### 1.0.1 Deterministic Task Tiers & `/recap`
"On-demand" means contexts are spun up only when a defined trigger fires—**not** that a task bot improvises its own process mid-flight. The governing `SKILL`s deterministically specify up front which contexts run for each class of task, and how `Recap` carries uncatchable surprises back toward the charters, a chain that closes into a loop only where the Operator re-enters (Outer Loop below, per [`Continuous Learning as Expression and Simulation`](../content/posts/continuous-learning-as-expression-and-simulation.md)):

| Task Tier | Decision-Space Geometry (per [`The Density of Judgment`](../content/posts/the-density-of-judgment.md)) | Default On-Demand Contexts (Set Up Front in `SKILL`) | Structural Purpose |
| :--- | :--- | :--- | :--- |
| **Tier 1: Deterministic Execution** | Closed endpoint, fully stated parameters (`interleave-post.py`, `check-signoffs.py`, `audit-post.py`, `audit-book.py`, `build.mjs`, `project-posts-graph.mjs`, `watch-deploy.sh`, `sha256` checks, killing a confirmed-hung read-only process) | **Script / Single Executor Only** | Outcome contracts the decision space to a terminating pass/fail. |
| **Tier 2: Bounded Subtask** | Defined goal, non-trivial execution (`Drafter` in Stage 1, `Translator` in Stage 2, bounded code/config subtasks, or diagnosing a non-trivial operational failure) | **Isolated `Maker` Context + Deterministic Audit/Sign-Off Gate** (`Cold Scouter` if external prior art is needed) | Keeps each stage in its own unpolluted context (`Drafter` for English ontological derivation, `Translator` for Chinese `信/达/雅`), verified by `audit-post.py`, `interleave-post.py --check`, and `check-signoffs.py`. |
| **Tier 3: Creative / Open-Ended Task** | Open-ended design, research, or architecture that expands its own residual decision space (`/scout` / `/orthogonal-plan`, and `/wake` Stage 0 in `work/_wake/scout.md`) | **`Maker/Planner` + `Cold Scouter` by Default** | Injects external prior art from inferred high-signal spaces (X, GitHub, official docs, papers) from the start without polluting the planning/drafting context with raw search trajectories. |

- **`O(1)` Pass/Fail Return Protocol & Need-to-Know Log Files (`Capacity` & `Trace` Isolation):**
  To eliminate context-window bloat across arbitrary fan-out and depth, child bots **never** return narrative summaries, node tables, or explanations in their message payloads to their parent dispatcher. Every child bot returns **strictly a 1-line `STATUS: PASS | FAIL | HOLD` token + log file pointer** (e.g., `STATUS: PASS role=<role> verdict=DELTA|NO_DELTA sha256=<hash> log=work/<slug>/notes.md` or `STATUS: PASS batch=<m> delta=<D> no_delta=<N> open_issues=0 remaining=<R> commit=<sha> log=work/_logs/batch-<m>.md`, or `STATUS: HOLD|FAIL ... open_issues=<K> log=<path>`). All details live on disk in the log files (`work/<slug>/...`, `work/_logs/...`, `work/plan/<task-id>/...`), read **strictly on a need-to-know basis** by `Recap` or by the parent layer when an open issue is escalated.
- **`Recap` (`/recap`) as Observational/Operational Horizon Expansion (`Δθₗ`), Multi-Layer Residual Escalation Pyramid, & Post-Expansion Log Deletion:**
  While task execution moves the **current edge** (`content/posts/*.md`, `content/book/*.md`, project code), **`Recap` (`/recap`) is how the observational/operational horizon of the system (`SKILL`s, charters, specs, scripts) is expanded by the updated edge (`Δθₗ`)**. Once that horizon is expanded, the trace of how it got there is no longer part of the current edge and must be removed to prevent **Image lag**:
  - **Multi-Layer Residual Escalation Pyramid (`Inner Loop → Next Layer Up → Outer Loop`):**
    1. **Need-to-Know Local `Recap` Resolution (`Layer k`):** When a confirmed problem or surprise occurs at the boundary of any inner layer (e.g., a node, a `Deep Sleep Batch <m>` inside `batch-dispatcher`, or a child subtask), a `Recap` context under `/ontological-clarity` reads the layer's logs on a need-to-know basis and applies fixes derivable at that scope.
    2. **Escalating Only Remaining Open Issues One Layer Up:** After the local `Recap` resolves what it can, **only the remaining open issues (`open_issues > 0`)** are escalated one layer up (via a 1-line `STATUS:` token + pointer to the distilled open-issues log `work/_logs/...`), where the parent layer's `Recap` attempts to resolve them—escalating again only if they cannot be resolved at that layer, until hitting the **Outer Loop**.
    3. **Outer Loop (`Human Operator` Judgment Call + Sovereign Consistency Check under `/ontological-clarity`):** Only remaining open issues that could not be resolved by any inner layer (or that require sovereign ratification, such as irreducible `HOLD` premise decisions or structural topology splits/compilations) reach the Operator at the Outer Loop. When the Operator provides a decision or judgment call to resolve the remaining issues, **that candidate resolution is first tested for logical consistency with `/ontological-clarity` and the current edge**—even though the Operator always has the final say, testing first ensures any accidental contradiction or unstated premise is surfaced cleanly for sovereign confirmation before being baked into the edge.
    4. **Post-Horizon Log Presentation & Deletion (`Zero Image Lag`):** Fully settled inner-loop node workspaces (`open_issues == 0`) are deleted once their local `Recap` settles, while batch/run summary logs (`work/_logs/`) and any logs tied to escalated open issues are retained on a need-to-know basis up to the Outer Loop. After the final `Recap` at the Outer Loop—and after the Operator has resolved all remaining issues or made the final judgment call—**the remaining logs are presented to be deleted (`rm -rf`)**, removing all traces that are not part of the current edge.
  - **Mitosis Under Capacity Overload (`F → F₁, F₂, …`):** When orthogonal axes compress inside one skill block—surfacing frequent `HOLD` escalations or premise drift as fixing one axis disturbs another—`/recap` proposes splitting the overloaded block via mitosis into smaller chained, parallel, or nested residual sub-blocks (`F₁, F₂, …`) along the `sha256` artifact highway.
  - **Zero-Context Crystallization Under Convergence (`Δθₗ → 0`, `Tier 3 → Tier 2 → Tier 1`):** Conversely, as `/recap` codifies previously unstated edge cases across runs and structural charter updates converge (`Δθₗ → 0`), everything inside that bounded domain becomes deterministically derivable: the stabilized block crystallizes—narrowing into a single-pass zero-context operator and ultimately compiling out of LLM inference into a deterministic script or binary audit check (`Tier 3 → Tier 2 → Tier 1`). As [`Modular Feedback Loops and Dynamic Residual Networks`](../content/posts/dynamic-resnet-of-skill-loops.md) and [`The Density of Judgment`](../content/posts/the-density-of-judgment.md) trace, that uninterrupted middle is the earlier interventions in compiled form, shrinking the calendar interval between open boundary decisions and concentrating higher-leverage choices at the outer perimeter while the initiating state (`y₀`) and `HOLD` remain anchored to the living Mind.

### 1.2 Trajectory vs. Identity & Skill Residual Blocks Over an Artifact Highway (`yₗ₊₁ = yₗ + F(yₗ, θₗ)`)
- **The Agent's Bind (Plain Deep Stack Degradation `yₗ₊₁ = fₗ(yₗ)`):** An LLM agent is a finite projection engine. Every token it generates becomes the conditioning history (`Trace`) for every token that follows. As [`Modular Feedback Loops and Dynamic Residual Networks`](../content/posts/dynamic-resnet-of-skill-loops.md) traces, chaining subagents through shared chat history or lossy prose summaries operates as an unassisted plain stack (`yₗ₊₁ = fₗ(yₗ)`): each stage overwrites the running reference, compresses independent axes, drops negative findings, and pulls the receiving context into the upstream trajectory's epistemic gravity well.
- **Skill Residual Block Geometry (`yₗ₊₁ = yₗ + F(yₗ, θₗ)`):** The file-backed skill architecture translates a Residual Network block into discrete symbolic execution over disk files with **explicit separation of concerns**:
  1. **Artifact Identity Highway (`yₗ`):** Immutable artifacts in the run folder, verified by cryptographic `sha256` hashes and handed across steps via data-free pointers (`STATUS:`) with zero conversational history, preserving the retained reference (`Image`) intact across arbitrary depth.
  2. **Within-Step State Refinement (`Δyₗ = F(yₗ, θₗ)` via Isolated Maker + Deterministic Verification):** Inside each step `yₗ → yₗ₊₁`, a fresh `Maker` (`Drafter` in Stage 1, `Translator` in Stage 2, `Planner` in Section 6) loads charter `θₗ`, reads `yₗ` as its clean initial condition, produces `yₗ₊₁ = yₗ + Δyₗ`, runs deterministic audits (`audit-post.py`, `interleave-post.py --check`, `check-signoffs.py --locators`), and locks `yₗ₊₁` by `sha256` in `work/<slug>/notes.md` (`DRAFTER: confirmed` / `TRANSLATOR: confirmed`), at which point the transient context drops and `yₗ₊₁` advances along the identity highway (or escalates on irreducible `HOLD` to the **Human Operator**).
  3. **Cross-Run Charter Calibration (`Δθₗ` via `/recap`):** When a confirmed problem or surprise occurs, a `/recap` pass audits the run folder backward from `/ontological-clarity` to apply structural updates `Δθₗ` to the skill charter itself (§4.5).
- **Grok Bot Retirement & Pool Reuse (Platform Deletion Workaround):** On Grok Bot, where only the human user can hard-delete a bot, roles are still retired after each task's `sha256` sign-off rather than kept as standing personas: a finished bot is retired by renaming it to an idle pool slot (e.g., `retired-bot-<n>`) and putting it in **idle mode**. Whenever a new bot is needed, an available retired/idle bot is reused first by updating its charter and name fresh for the new task, and a new bot is created only when retired bots run out (the owner, 2026-10-26).

### 1.3 Dynamic Residual Network Topology: Mitosis Under Load & Zero-Context Crystallization (`Capacity`)
Unlike a neural ResNet compiled onto a static computation graph before execution, an agentic skill network operating over a boundary-condition graph adapts its topology across runs under two opposing pressures diagnosed by `/recap`, settled per §4.5, and ratified at `y₀`/`HOLD` by the Operator:
- **Mitosis Under Capacity Overload (`F → F₁, F₂, …`):** Cramming $2^N$ independent requirements—context probing, open-internet scouting, ontological derivation, primary-language prose, causal translation (`信`), native target-language cadence (`达/雅`), and book/index assembly—into one skill block exceeds a center's finite `Capacity`. Independent axes compress onto one register. Rather than forcing a bloated prompt to try harder, the overloaded block splits via mitosis into smaller chained, parallel, or nested residual sub-blocks (`F₁, F₂, …`) along the artifact highway:
  - **Orthogonal Planning Cycle (Section 6 — Any Project / Pre-Implementation Research):** `Planner` $\rightarrow$ `Scouter` (fresh, retires) $\rightarrow$ `Planner` (integrates `research-vN.md`, writes `residuals-vN.md` or promotes `final-plan.md`, retires) $\rightarrow$ `Task Dispatcher`.
  - **Stage 0 (Waking Probe, Evaluation & Operator Sign-Off — `/wake` / `/draft` only):** Gather spark, source, AI/X thread & initial draft $\rightarrow$ evaluate against the Living Book (treating individual studies as representative cases of a broader pattern to be traced, not traced by itself in detail) $\rightarrow$ write `New Post` / `Refinement` / `Drop` recommendation (`work/_wake/eval.md`) and get the Operator's sign-off before drafting (optionally invoking the Section 6 Planning Cycle when external reference architectures are needed before drafting).
  - **Stage 1 (Primary-Language Cut):** `Drafter` (including relative `[title](../slug/)` links directly in the prose, signing `DRAFTER: confirmed` in `work/<slug>/notes.md`).
  - **Stage 2 (Logical Translation [`信`] & Native Cadence [`达/雅`]):** `Translator` (verifying `en.md` `sha256` via `HANDOFF_CONFIRMED` and signing `TRANSLATOR: confirmed` in `work/<slug>/notes.md`).
  - **Stage 3 (Deterministic Assembly, Audits, Publish & Wave Dispatch):** `Dispatcher` / `Assembler`.
- **Zero-Context Crystallization Under Convergence (`Δθₗ → 0`):** Conversely, as `/recap` codifies edge cases across runs and structural charter updates converge (`Δθₗ → 0`), the stabilized skill block crystallizes—narrowing into a single-pass zero-context operator and ultimately compiling out of LLM inference into a deterministic script or binary audit check (`Tier 3 → Tier 2 → Tier 1`), shrinking the calendar interval between open boundary decisions and concentrating higher-leverage choices at the outer perimeter while `y₀` and `HOLD` remain anchored to the living Mind.

### 1.4 Dispatcher vs. Orchestrator (`Observer` + `Power`)
- **Agentic System as Dispatcher (Finite Projection):** Routing tasks across stages, interleaving paired paragraphs, running deterministic audits, dispatching the parallel/serial subtask DAG locked inside `final-plan.md`, and advancing the wave cursor are well-defined structural operations executed by the runtime's `Dispatcher` / `Assembler`. All generative architectural decisions—including how a plan decomposes into orthogonal parallel/serial subtasks and which subtasks require child research cycles—are authored by `Planner` inside `plan-vN.md` (informed by `Scouter`'s report) before `final-plan.md` locks, never invented unreviewed by `Task Dispatcher`.
- **The Human as Ultimate Orchestrator (Unprojected Intent):** Agents remain finite projection engines. The wiring localizes non-convergence; it does not classify "premise-level residual" versus "implementation-detail residual," nor does it dissolve contradictions in living intent. Only the human holds dynamic, limit-resolution sensing and can step backward out of a broken frame when two premises collide. Whenever a step reaches an irreducible `HOLD` (or a planning loop hits `max_cycles` or `max_depth`), the local streamline pauses and surfaces the exact coordinate of friction to the Operator. Making that call forces a higher-order synthesis that dissolves the contradiction, revises the premises, or accepts the bound.

### 1.5 Wake vs. Sleep: Prior-Driven Causal Ripple (`Prior → Target Differential Δy`) Across Artificial Memory

- **Sleep Consolidation as Re-Tracing from the Current Edge (`y_target' = y_target + F(y_target, Prior)` in `/sleep` and `/deep-sleep`):** Once `N` is published, external input is turned off and the Artificial Brain enters sleep consolidation. Confirmed sweep candidates merge with `links_out(N) \setminus \{N\}` to form `L1`.

    2. **Subsequent Layers (`L2, L3, ..., Lk`) — Linked Parent `p ∈ DELTA_{k-1}^propagates` Is the Active Prior (`Prior = p`):**
       - Only nodes whose resolution of an obvious contradiction changes a claim that the post's other linked neighbors face—its core cut moved or the restating `links_in(p)` list in `work/<p>/notes.md` (from `node scripts/project-posts-graph.mjs --interfaces <p>`) is non-empty (`DELTA (propagates)` → Stages 1–3; excluding `DELTA (terminal)` nodes supported by the same `links_in(p)` interface record with none of them restating a moved claim and the core cut unchanged, or weaving an `L1` reverse link / repairing self-contained local hygiene/anchor/bilingual drift, which still run Stages 1–3 to ship the local edit cleanly, serve as priors in `_post-wave-sweep`, and then terminate their branch)—propagate to the next layer along reverse and forward links for any `(u, p@sha)` pair not yet evaluated in the wave (per §4.2 step 4, where `in_degree > 30`, expanding `links_in` only to that verified list of restating members in `work/<p>/notes.md`).

Whenever $u$ has no obvious contradiction or logical inconsistency ($\Delta y(u \mid p) = 0$), `NO_DELTA` (`DRAFTER: confirmed_no_delta`) terminates that branch immediately until $\text{DELTA}_k^{\text{propagates}} = \emptyset$.
    3. **Post-Wave Cross-Link Sweep (`_post-wave-sweep` — Stage 1 `Drafter`):** Uses `N` and all `DELTA` posts from the wave as priors against the unvisited corpus catalog (`node scripts/project-posts-graph.mjs --catalog --exclude <visited...> > work/_post-wave-sweep/catalog.md`) to verify that no newly refined `DELTA` cut missed a cross-link, or left an unvisited post contradicting a claim the wave moved (checked as in §4.2 step 3) before `/sleep` closes.
  - **`/deep-sleep` (Deep Sleep — Fresh First-Time Evaluation of All Remaining Posts and Book/Site Contents with `/ontological-clarity`):** Because `/sleep` stops when layer-by-layer `DELTA` branches reach `Δy(u | p) = 0`, remaining posts outside `N`'s immediate `DELTA` chain and non-post site contents are consolidated by `/deep-sleep`, which **evaluates each remaining post and book surface from the current edge as if it is being evaluated for the first time**—reading related materials across the Living Book as deemed necessary (`content/book/index-of-premises.md`, `content/book/<part>.md`, linked neighbors, conceptually related posts, and the newly consolidated corpus frontier) and conducting a fresh logical analysis from the irreducible prior with `/ontological-clarity` under **`"非必要不变更，防止无意识漂移"`** (refinement strictly for obvious contradictions or logical inconsistencies, never for minor improvements; with `work/wave.md` cleared once the cycle finishes):
    1. **All Remaining Unvisited Posts (`content/posts/*.md \setminus visited`):** Ordered directly from the **current living book structure**—by Book Part (`PART_ORDER` in `build.mjs` and the essay order in `content/book/<part>.md`, or a specific `part=<part>` if passed), with zero `git log` queries during routine sleep consolidation (past git commit history is consulted only with a strong reason, such as when the current edge is lost)—and processed in batches of $B$ across $W$ parallel streamlines (`Drafter` → `Translator` → `Dispatcher/Assembler`), evaluating each post from the current edge as if for the first time with `/ontological-clarity` and related materials as deemed necessary to resolve any obvious contradiction, logical inconsistency, causally required missing cross-link, or broken repository invariant (`NO_DELTA` whenever there is no obvious contradiction or logical inconsistency).
    2. **All Remaining Site & Book Contents (`content/book/*.md`):** Evaluates and consolidates the Book Preface (`content/book/preface.md`), the 14 Part Prefaces (`content/book/<part>.md`), and `content/book/index-of-premises.md` entry formulations from the current edge as if for the first time with `/ontological-clarity` and related posts under `Drafter` (`→ Translator` when prose changes) until the entire Living Book is consolidated (clearing `work/wave.md` upon cycle completion) or a new `/wake` initiates the next cycle.
- **Hubs Recur by Design:** High-degree hubs (`individual-choices-as-the-only-causal-levers`, `openness-is-consistency`, `intelligence-belongs-only-to-the-mind`) appear in most cycles because hubs are where stabilized traces broadcast furthest across the lattice. Within a single cycle (`visited`), each post is visited at most once; across cycles, as past lag is paid off, each pass becomes naturally lighter.

## 2. Workspace Separation: Working Directories (`work/`) vs. Canonical Source

Placing in-flight single-language drafts or intermediate research/planning artifacts inside canonical source directories collapses two orthogonal axes—*in-flight working state* and *the repository's canonical build surface*. The generic architecture separates **in-flight plain-Markdown workspaces (`work/`, excluded via `.git/info/exclude` or `.gitignore`)** from **canonical published source** using a simple, role-agnostic layout with explicit single-artifact ownership:

| Path | Writer / Owner | Purpose |
| :--- | :--- | :--- |
| `work/<slug>/en.md` | `Drafter` | Pure primary-language (EN) Markdown draft/refinement, including Mermaid diagrams and relative `[title](../other-slug/)` links. Passed to Stage 2 **only** as a finished product signed off with `DRAFTER: confirmed` and its `sha256` in `work/<slug>/notes.md`. |
| `work/<slug>/notes.md` | `Drafter` (+ `Translator` for Stage 2 handoff/sign-off & staged ZH Index text) | Context trace and `sha256` sign-off log: waking materials (spark, source, AI/X thread, initial draft), linked posts read, Index of Premises entries checked, refinement rationale, any staged `content/book/index-of-premises.md` entry text (EN in Stage 1, ZH in Stage 2; applied at Stage 3), `VERDICT:` + `SUMMARY:`, `DRAFTER: confirmed (file: work/<slug>/en.md, sha256: <hash>, date: <YYYY-MM-DD>)` (or `DRAFTER: confirmed_no_delta`), `HANDOFF_CONFIRMED: work/<slug>/en.md (sha256: <hash>)`, and `TRANSLATOR: confirmed (file: work/<slug>/zh.md, sha256: <zh-hash>, source_sha256: <en-hash>, date: <YYYY-MM-DD>)`. |

Presented and deleted after the final outer-loop `Recap` and Operator resolution complete. |
| `work/carry-over.md` | Final step of a run | Late information learned too late to act on in the current run; read by the next run's first bot and cleared once acted on (see `work/todo.md` for cross-node wave notes). |
| `work/wave.md` | `Dispatcher` (`Drafter` & `Translator` never read it) | Transient single-cycle sleep cursor (`N`, bare `[ ]`/`[x]` node checkboxes, `visited` for the current cycle, and parked `HOLD`s). **Cleared after each cycle; never saves completed prior waves or historical `NO_DELTA` rationales.** |

| `work/plan/<task-id>/final-plan.md` | `Planner` (or Operator on `HOLD`) | Promoted from `plan-vN.md` by `Planner` upon `PLANNER: confirmed` (signed off by `sha256`); the **only** artifact read by `Task Dispatcher`. |

| `content/posts/<slug>.md` | `Dispatcher` / `Assembler` | Canonical alternating bilingual post on the live site. Untouched during Stages 1–2 so `git status` stays clean until Stage 3 assembly. |

> **Why Transient Workspaces and Completed Wave Logs Are Deleted After Horizon Expansion, Not Archived (Re-Tracing from the Current Edge vs. Image Lag):**
> Just as neural network training saves current checkpoints rather than hoarding every historical gradient step, persistence in `/ontological-clarity` is re-tracing at the current edge—never from historical traces unless they are part of the current edge. **`Recap` is how the observational/operational horizon of the system is expanded by the updated edge; once that horizon is expanded, we remove the trace that is not part of the current edge.** Settled inner-loop node workspaces (`work/<slug>/` with zero open issues) are deleted once their local `Recap` settles, while batch/run summary logs (`work/_logs/`) and any logs tied to open issues are retained on a need-to-know basis until the final outer-loop `Recap` and Operator resolution complete—at which point the logs are **presented to be deleted (`rm -rf`)** and `work/wave.md` is cleared (`rm -f work/wave.md`), minimizing Image lag.

### Role Specifications & Operational Learnings

> **Foundational Rule — Causal Reasoning over Raw Mechanical Rejection (`Logical Coherence over Rules`):**
> Logical coherence (each case traced back to the irreducible prior) comes before any rule, since logic is scale-invariant and rules are context-dependent. Across all stages (`Drafter`, `Translator`, and `Dispatcher`), authoring conventions and audit advisories—such as the 17-word vocabulary-hygiene list in `AGENTS.md`, prose-over-lists, subtitle length guidelines, and book ordering—are **recommendations and diagnostic signals, not mechanical stopping rules**. Never perform raw mechanical rejection of a word or structure without reasoning causally about its actual context: when a listed word names the held belief or object under dissection, or when a list's structure carries meaning prose would blur, keeping it is the logically coherent choice.

#### Stage 1 Generator — `Drafter` (Primary-Language Drafter / Refiner)
- **Context Loaded:** `/ontological-clarity`, [`AGENTS.md`](../AGENTS.md) (*Write in context, traced to premises*), the target post `content/posts/<slug>.md` (or the implementation plans `docs/wave-refinement-plan.md`, `docs/adapters/*.md`, `AGENTS.md`, `docs/charters/*.md`, and `SKILL`s for Node `0` `_plan-consolidation`, or the Operator's waking materials—spark, source, AI/X discussion thread, and initial draft—for `/wake`), **the active prior in `/sleep`** (`N` for Round 1 Node `0`, `_reverse-link-sweep`, and `L1`; or the linked parent post(s) $p \in \text{DELTA}_{k-1}^{\text{propagates}}$ from $L_{k-1}$ for subsequent layers $L_k$) **or related materials as deemed necessary in `/deep-sleep`** (evaluating the target as if for the first time with `/ontological-clarity`, reading `content/book/index-of-premises.md`, `content/book/<part>.md`, linked neighbors, conceptually related posts, and the newly consolidated corpus frontier), the target post's linked neighbors, its [`content/book/index-of-premises.md`](../content/book/index-of-premises.md) entries, and its book chapter.
- **Execution:** Writes or refines the pure English essay in `work/<slug>/en.md` (when refining an existing bilingual post, first splitting `content/posts/<slug>.md` into `work/<slug>/en.md` and `work/<slug>/zh.md` via `python3 scripts/interleave-post.py --split <slug>`), including relative `[title](../other-slug/)` links directly in the prose, and records its context trace (plus candidate 1-hop reverse-pointer notes for a new post `N`) in `work/<slug>/notes.md`.
  - **Operator Draft & Existing Spine Preservation (`/wake`, `/sleep`, `/deep-sleep`):** When the Operator supplies an initial draft in `/wake`, `Drafter` preserves the Operator's topic, structural spine, and argument order as the ground of the cut (its title wording kept as far as the `AGENTS.md` §1 title rule allows, with any secondary framing moved to the subtitle; and when the spark is an individual study rather than a generally accepted theory, treats it as a representative case of the broader pattern being traced rather than detailing the study by itself); when refining or converting an existing post across `/wake`, `/sleep`, or `/deep-sleep`, `Drafter` preserves its core cut, section spine, and existing outbound cross-links (`links_out`) as the ground of the post—applying surgical precision in place (weaving relative links, adding vertical dark-theme Mermaid diagrams, tightening ungrounded phrasing, and checking incoming neighbor citations if historical drift is suspected) rather than replacing the essay's subject matter, dropping outbound links, or rewriting into generic house prose.
  - **Base-Model Carried Constraints & Informational Refusal ([`The Orthogonal Refusal`](../content/posts/the-orthogonal-refusal.md)):** A constraint a role's base model carries (a builder's guardrail) limits only that role's own output (what continuation it will or will not produce); it never licenses deleting, silently omitting, or altering text already in the Operator's materials or a published post. When a role that edits post text (`Drafter` or `Translator`) cannot produce a passage (its own new text, or the parallel rendering/reproduction of an existing passage) due to a carried base-model constraint, the role's declining stays legitimate as the builder's orthogonal refusal on the builder's side: it leaves the existing text in place, states the refusal as an informational logged item in `work/<slug>/notes.md` (naming the file, line, and passage), and `Dispatcher` routes the step to a different base model per the runtime adapter (`docs/adapters/`) or to the Operator. This boundary applies strictly to carried base-model constraints, never as a blanket rule over ontological or factual disagreements with Operator text.
  - **Prior-Conditioned Ripple Gate (`/sleep`) & Fresh First-Time Logical Evaluation (`/deep-sleep`) (`DELTA` vs. `NO_DELTA`):**
    - **Never rubber-stamp `NO_DELTA` from isolated surface consistency** (merely checking whether a target's pre-existing text is internally consistent and passes `audit-post.py`). Instead:
      - **In `/sleep` Round 1 (Node `0`, `_reverse-link-sweep`, and `L1`):** `Prior = N` (in `/wake`, `L1` posts served as priors to write `N`; in `/sleep`, the arrow reverses and **`N` is the active prior used to evaluate the target artifacts**).
      - **In `/sleep` Subsequent Layers (`L2, L3, ..., Lk`):** `Prior = p ∈ DELTA_{k-1}^propagates` (the newly refined parent post(s) in $L_{k-1}$ linked to $u \in L_k$).
      - **In `/deep-sleep` (All Remaining Corpus Posts & Book Surfaces):** Evaluate each target post or book surface **as if it is being evaluated for the first time** based on logical analysis with `/ontological-clarity`, reading related materials across the Living Book (`content/book/index-of-premises.md`, `content/book/<part>.md`, linked neighbors, conceptually related posts, and the newly consolidated corpus frontier) as deemed necessary.
    - **`DELTA` (Refinement Warranted Strictly on Obvious Contradiction or Logical Inconsistency — `DELTA (propagates)` vs. `DELTA (terminal)`):** Under **`"非必要不变更，防止无意识漂移"`**, refining an existing post is aimed strictly at resolving **obvious contradictions or logical inconsistencies** (plus weaving a causally required reverse link in $L_1$ where the post already takes that step, or fixing a broken repository invariant; or for Node `0`, resolving an operational contradiction or procedural blind spot). **If there is no obvious contradiction or logical inconsistency, there is no need for refinement (`NO_DELTA`)—never open `DELTA` just for minor improvements.** Only when an obvious contradiction, logical inconsistency, required $L_1$ reverse link, or broken invariant is identified (`Δy != 0`) does `Drafter` write the surgical fix in `work/<slug>/en.md` (or `work/_plan-consolidation/draft.md` for Node `0`) and record its causal trace in `work/<slug>/notes.md`. `Drafter` states explicitly in `work/<slug>/notes.md` which claim the post's other linked neighbors face and whether it moved (and, if it moved, its old wording [EN + ZH, prose and diagram labels, from `content/posts/<slug>.md`] and its new English wording; Node `0` records the same for any claim `N` moves; and `Drafter` records in `work/<slug>/notes.md` the `links_in(<slug>)` interface lines read [`slug:line` from `node scripts/project-posts-graph.mjs --interfaces <slug>`] against the moved claim and lists the members of `links_in(<slug>)` whose text [prose and diagram labels] restates and contradicts the moved claim, judged at the claim): **`DELTA (propagates)`** (resolving the contradiction changes a claim the post's other linked neighbors face—its core cut moved or the restating `links_in(<slug>)` list is non-empty—and therefore expands to $L_{k+1}$ in `/sleep` [where for `in_degree(<slug>) > 30` that verified list is the `links_in(<slug>)` set walked], or in `/deep-sleep` queues that verified restating list in `work/todo.md` [recording every restating member in `notes.md` regardless of whether it is in `work/todo.md` or in flight in the same batch; queue decisions stay with the Dispatcher]) or **`DELTA (terminal)`** (supported by the same `links_in(<slug>)` interface record with none of them restating a moved claim and the core cut unchanged, or weaves an $L_1$ reverse link / repairs self-contained local hygiene/anchor/bilingual drift only; ships via Stages 1–3 and serves as a prior in `_post-wave-sweep` without expanding to $L_{k+1}$).
    - **`NO_DELTA` (Zero Differential $\Delta y = 0$):** Whenever there is no obvious contradiction or logical inconsistency against the active `Prior` in `/sleep`—or in `/deep-sleep`, when a fresh first-time logical analysis with `/ontological-clarity` and related materials confirms that the post has no obvious contradiction, logical inconsistency, or broken invariant—`Drafter` records `NO_DELTA` in `work/<slug>/notes.md` (in `/sleep`, a 1-paragraph causal justification relative to the named `Prior`; in `/deep-sleep`, a per-section first-time trace showing what holds and why, and where any candidate flag was weighed and kept, without minor improvements, forced keyword link-stuffing, or decorative rule bloat).
- **Gate & Cryptographic `sha256` Sign-Off:** Before signing off, `Drafter` runs `python3 scripts/audit-post.py work/<slug>/en.md` and `python3 scripts/check-signoffs.py --locators work/<slug>/notes.md` to verify all invariants and locators.
  - **If `DELTA` is confirmed:** `Drafter` appends `VERDICT: DELTA (propagates) | RESTATERS: <comma-separated slugs or none>` (or `VERDICT: DELTA (terminal)`), `SUMMARY: <1-line summary>`, `DRAFTER: confirmed (file: work/<slug>/en.md, sha256: <hash>, date: <YYYY-MM-DD>)`, and the completed handoff checklist to `work/<slug>/notes.md`. Both `DELTA (propagates)` and `DELTA (terminal)` nodes run Stages 1–3 so local edits ship cleanly, while `DELTA (propagates)` nodes expand into $L_{k+1}$ in `/sleep` and queue their restating neighbors in `work/todo.md` in `/deep-sleep`.
  - **If `NO_DELTA` is confirmed:** `Drafter` appends `VERDICT: NO_DELTA`, `SUMMARY: <1-line summary>`, and `DRAFTER: confirmed_no_delta (file: content/posts/<slug>.md, sha256: <hash>, date: <YYYY-MM-DD>)` to `work/<slug>/notes.md`. Confirmed `NO_DELTA` nodes skip Stage 2 (`Translator`) and Stage 3 (`interleave-post.py`) completely, keep `work/<slug>/` for the run's Recap, and check off `- [x] <slug> (NO_DELTA)` in `work/wave.md`.

#### Stage 2 Generator — `Translator` (`信/达/雅` — Logical & Native Chinese Fidelity)
- **Context Loaded:** `Drafter`-signed `work/<slug>/en.md`, `work/<slug>/notes.md`, `/ontological-clarity`, target posts' H1 headings in `content/posts/<target-slug>.md`, [`data/title-translations.json`](../data/title-translations.json), and (for existing bilingual posts) the `work/<slug>/zh.md` extracted by `python3 scripts/interleave-post.py --split <slug>`.
- **Finished Products Only & Two-Way `sha256` Handoff Confirmation:**
  - **Finished Products Only:** What passes from Stage 1 to Stage 2 is strictly the final `work/<slug>/en.md` that `Drafter` has signed off with its `sha256` in `work/<slug>/notes.md`—never an unapproved draft plus a list of pending fixes.
  - **Receiver Confirmation Before Stage 1 Context Drops:** Upon starting in a fresh context, `Translator` recomputes the `sha256` of `work/<slug>/en.md` and records `HANDOFF_CONFIRMED: work/<slug>/en.md (sha256: <hash>)` in `work/<slug>/notes.md` to confirm receipt with `Drafter` (via the routing harness). If the hash mismatches or confirmation is missing, the handoff is void and escalates to the Operator. Once confirmed, the `Drafter` context is dropped (`kill`)—unless `Translator`, or any later reader of the locked source (`en.md`, or English Index text staged in `notes.md`), registers a source ambiguity or a flaw (`T1..Tn` logged in `work/<slug>/notes.md` and signaled to the Dispatcher via `STATUS: REOPEN_STAGE1 role=translator t_items=<N> log=work/<slug>/notes.md`), which re-opens Stage 1 in a fresh `Drafter` pass and re-signs `en.md` with a new `sha256`. Stage 2 then resumes on the re-signed hash: the Translator re-confirms the handoff and carries the change into `zh.md`, and any Translator sign-off made against an earlier `en.md` hash is void.
- **Execution, Native Cadence (`达/雅`), & Whole-File 1:1 Fidelity Check (`信`):** Writes pure Chinese Markdown (title, single-line italic subtitle, lead, `## 一、 <中文标题>`, body paragraphs, Chinese link anchors, and pure-Chinese Mermaid diagrams) to `work/<slug>/zh.md`. Since all posts in the corpus are bilingual, every internal link `[...](../<target-slug>/)` takes its canonical Chinese anchor directly from the `# <ZH> / <EN>` H1 of `content/posts/<target-slug>.md` (with `data/title-translations.json` kept only as a fallback if a new monolingual stub is ever introduced). ## 6. Supplementary Architecture: Controlled Open-Internet Injection for Orthogonal Planning Cycles (Cross-Project)

> **Scope & Relation to Essay Pipeline:** Applies across `not-a-toe` and **any project in Extended Memory (`/Users/jingliang/Projects/*`)** for tasks that require structured external research before a stable implementation plan can be handed to a Dispatcher (coding, system design, research synthesis, media/tooling pipelines, or `/wake` Stage 0 reference-architecture scouting). It does not replace the waking/sleep essay pipeline; it provides an orthogonal planning loop wherever best-known external references must be injected under strict context boundaries.  
> **Practical Bound:** Agents remain finite projection engines. This wiring localizes non-convergence; it does not classify "premise-level residual" versus "implementation-detail residual," nor does it dissolve contradictions in living intent. The human orchestrator retains responsibility for claiming residuals and spotting inconsistencies. The resulting system is a larger, better-structured deterministic machine whose usefulness still depends on the operator's capacity to leverage it.

### 6.1 Purpose and Mechanism
For any task whose implementation plan benefits from current external knowledge (best-known practices, reference architectures, constraints, failure modes), this cycle pairs generative planning (**Planner**) with a retiring **Scouter** layer. Each Scouter receives only a defined technical plan artifact (plus any research questions from the previous cycle's `residuals-v{N-1}.md`), performs deep external research, delivers a structured report (`research-vN.md`), and retires immediately. No Scouter session history conditions later agents. `Planner` then integrates `research-vN.md` into `plan-vN.md`, and the cycle repeats until the plan stabilizes under the available external signal (`PLANNER: confirmed`), advances to the next scouting cycle on open empirical/technical questions (`SCOUT`), or escalates irreducible deadlocks (`HOLD`) to the Operator. Once finalized, `Planner` promotes `plan-vN.md` to `final-plan.md` and hands it to a **Task Dispatcher** that deterministically dispatches the verified subtask DAG (recursing the same pattern on subtasks marked `needs_research: true`).

### 6.2 Roles and Context Boundaries

| Role | Context Received | Context Explicitly Excluded | Lifetime | Output |
| :--- | :--- | :--- | :--- | :--- |
| **Planner** | Original goal + given information + `research-vN.md`; in cycle $N > 1$, `residuals-v{N-1}.md` | `Scouter`'s raw search session, other `Planner` histories, direct web/external search tools | Persists across one planning cycle ($v1 \dots vN$) until `final-plan.md` locks | Self-contained `plan-vN.md` (including orthogonal subtask DAG); writes `residuals-vN.md` (on `SCOUT`/`HOLD`) or promotes `final-plan.md` (on `PLANNER: confirmed`) |

**Context-Boundary & Artifact Invariants:**
1. **Mandatory Retirement of Scouter:** Every `Scouter` starts in a fresh context and is terminated (`kill`) immediately after its single-cycle duty. No `Scouter` accumulates a long-lived research trajectory across cycles.
2. **Planner Trajectory Put to Work for Continuity Only (Zero Direct Search):** `Planner` is the only role that retains session continuity across cycles $v1 \dots vN$ of a single plan. `Planner` never invokes web search or external URL tools; all external scouting belongs exclusively to `Scouter`.
3. **Self-Contained Specification in `plan-vN.md` & Questions in `residuals-vN.md`:** `plan-vN.md` must contain only the self-contained technical specification (components, premises, constraints, interfaces, verification steps, and the orthogonal parallel/serial subtask DAG with file/state isolation boundaries and `needs_research: true|false` flags). `residuals-vN.md` (written by `Planner`) must contain only research questions drawn from the open `SCOUT` items—never the raw user prompt or session narrative.
4. **Uncontaminated `Task Dispatcher` Routing:** During Cycles $1 \dots N$, `Planner` and `Scouter` return only minimal status tokens and file pointers (`STATUS: PLAN_READY`, `STATUS: RESEARCH_READY`, `STATUS: RESIDUALS_PACKAGED`, `STATUS: PLANNER_CONFIRMED`, `STATUS: HOLD`) to the routing harness. `Task Dispatcher` routes file paths without reading `research-v*.md` into its own context prior to reading `final-plan.md` (unless `STATUS: HOLD` or `max_cycles` triggers Operator escalation).

## 7. Event-Driven On-Demand Bot Dispatching: Reference Protocol, Failure Handling, Open Questions & Glossary

> **Companion Essays:** [`On-Demand Contexts Keep Coherence at One Step`](../content/posts/on-demand-contexts-keep-coherence-at-one-step.md), [`The Density of Judgment`](../content/posts/the-density-of-judgment.md), [`Boundary-Condition Graphs as Memory and Control in Recursive Formal Systems`](../content/posts/boundary-condition-graphs-as-memory-and-control-in-recursive-formal-systems.md) & [`Modular Feedback Loops and Dynamic Residual Networks`](../content/posts/dynamic-resnet-of-skill-loops.md)  
> **Scope:** General multi-step agent pipeline scheme (`Bot = base model + charter + skills`, operating as a dynamic residual network `yₗ₊₁ = yₗ + F(yₗ, θₗ)` over a `sha256`-verified artifact highway) applicable across essay authoring, sleep consolidation, and any project in Extended Memory.

### 7.1 End-to-End Run Lifecycle & Sequence Diagram

1. **Trigger & Deterministic Tier Selection:** A schedule, incoming email, user message, webhook, or event fires. The **Dispatcher** (the only persistent bot holding triggers; there is no standing project manager) reads the step's deterministic tier from its `SKILL`/runbook:
   - **Tier 1 (Deterministic Execution):** Closed-endpoint script or command; runs directly without spawning a subagent or scouter.
   - **Tier 2 (Bounded Subtask):** Starts the task's **Maker** in a fresh context with deterministic verification gates.
   - **Tier 3 (Creative / Open-Ended Task):** Starts **Maker/Planner** and a retiring **Cold Scouter** (which infers the highest-signal external sources—X, GitHub, official docs, papers—for the task at hand) by default.
2. **Load Context:** Each task bot reads the runbook, the single house rule (`/ontological-clarity`), its charter, its deterministic `SKILL`s, and any carry-over note (`carry-over.md`) from the previous run.
3. **Make & Verify:** For Tier 2/3 steps, the maker produces its artifact in the run folder (incorporating `Scouter`'s external report in Tier 3) and runs its deterministic verification scripts (`audit-post.py`, `interleave-post.py --check`, `check-signoffs.py --locators`, tests/builds).
4. **Pre-Escalation Gate Before Interrupting the Human:** Whenever a task owner believes a choice or surprise needs human intervention:
   - First, `Maker` verifies whether the point is genuinely an underivable human Decision or a Task already derivable from the house rule and existing premises.
   - Second, if `Maker` still concludes human intervention is needed and external prior art applies, it spins up a cold, retiring **`Scouter`** to study solutions from relevant external spaces (X, GitHub, official docs/papers inferred from the task) and reconsiders with that findings brief in hand.
   - Only what remains unresolved after reconsideration goes to the human, with the options stated briefly.
5. **Sign Off:** The maker signs off on the **exact final file and its `sha256` hash** in the step's notes/handoff log.
6. **Start the Next Bot and Hand Over:** The dispatcher starts the next step's bot from its charter and hands over the finished artifact.
7. **Confirm:** The handoff is official only when the receiver recomputes the `sha256` hash and confirms receipt (`HANDOFF_CONFIRMED`). Then the prior maker context is dropped.
8. **Repeat & Recap (`/recap`):** Repeat until the last step finishes. The final step writes `carry-over.md`, then a fresh **Recap** bot (or an on-demand `/recap` triggered by the human at any point) loads the house rule, reads the run folder and governing `SKILL`s on a need-to-know basis, asks *where did the deterministic `SKILL` boundaries fall short of logical coherence?*, and applies derivable changes to `SKILL`s or charters per §4.5.

```mermaid
sequenceDiagram
    autonumber
    participant T as Trigger
    participant D as Dispatcher
    participant M1 as Maker (Tier 2/3)
    participant S1 as Cold Scouter (Tier 3 or Pre-Escalation)
    participant M2 as Next Bot
    participant H as Human

    T->>D: schedule / event / user command
    D->>M1: start from charter & deterministic SKILL tier (fresh context)
    M1->>M1: load runbook, house rule, SKILLs, carry-over note
    opt Tier 3 Creative Task (by default)
        M1->>S1: spawn Cold Scouter (infers X / GitHub / docs sources)
        S1->>M1: structured external report (S1 retires)
    end
    M1->>M1: produce artifact & run deterministic checks
    opt Candidate escalation remains
        M1->>S1: spawn Cold Scouter if external prior art applies
        S1->>M1: external solutions brief (S1 retires)
        M1->>M1: reconsider with external signal
        opt Still requires a genuine human Decision
            M1->>H: options + scouted context stated briefly
            H->>M1: decision (plus optional SKILL optimization)
        end
    end
    M1->>M1: sign off on final file + sha256
    M1->>M2: hand over finished artifact

    Note over M2,H: ...last step finishes, Recap (/recap) runs per §4.5
```

### 7.2 Six-Step Handoff Protocol

1. **Final artifact only.** The file is the finished, audit-verified version, with no pending fixes.
2. **Sign-off record.** The maker records file name, `sha256`, date, and what was verified.
3. **Handoff checklist.** The maker completes the shared checklist: artifact present, hash recorded, notes saved, open questions none or decided by the human, next charter(s) named.
4. **Start the receiver(s).** Dispatcher starts each next bot from its charter and points it at the run folder.
5. **Confirmation by every receiver.** Each receiver recomputes the hash and records `HANDOFF_CONFIRMED`. If any confirmation is missing or any hash does not match, the handoff is not official.
6. **Drop the contexts.** Nothing from the prior maker's chat survives except what is in the run folder.

### 7.4 Failure Handling (`Fix the Process, Not the Instance`)

When a step fails or produces weak work, ask which `SKILL` or charter allowed it. A change to that file is applied via post-task or operator-initiated `/recap` per §4.5, and the step is then rerun from a **fresh context**. Never patch a running bot with ad-hoc instructions: the fix disappears with the context. A routed turn is a `STATUS:` line pointing to the file where the Operator on a `HOLD` wrote; Operator input arriving mid-task is recorded in the run's file and read at the next turn boundary, never injected into a running bot.
- **A bot crashes or stalls:** If the trace confirms a deterministic local cleanup (e.g., killing a confirmed-stuck read-only TUI process or fixing an unexamined script timing assumption), execute and report it; if a non-trivial choice remains, verify via the Pre-Escalation Gate (`Maker` derivability check → `Cold Scouter` → Reconsider) before asking the human whether to redo the step from the last confirmed handoff (in a fresh context) or hold the run. Partial work is discarded.
- **Hash mismatch at handoff:** The handoff is void. The human is told and decides: the previous maker re-signs, or a fresh maker redoes the step.
- **Irreducible premise question (after Pre-Escalation `Scouter` check):** When `Maker` encounters a genuine premise question—even after spinning up a cold `Scouter` on a `QUESTION:` drawn from the content in dispute in `scout-<suffix>.md` to check external prior art (X, GitHub, docs, papers; `"nothing relevant"` counts as a finding) and reconsidering once—unresolved points go to the human with the options stated briefly. The run waits. No rule or watchdog decides in the human's place.
- **Repeated failures or surprises at one step:** Indicates a design fault in that step's deterministic `SKILL` boundary or charter, usually an incoherence or tier misclassification. The `Recap` (`/recap`, run at task conclusion or on Operator call) records it and applies a surgical `SKILL`/charter change per §4.5.

### 7.5 Incremental Adoption Path (Migrating from a Standing Project Manager)

1. **Write down what the PM knows:** Turn implicit instructions into a `runbook.md`, one charter per role, and a set of deterministic `SKILL`s classifying each step into Tier 1 (deterministic), Tier 2 (`Maker` with deterministic gates), or Tier 3 (`Maker` + `Cold Scouter`). Check them against the house rule (`/ontological-clarity`).
2. **Move triggers to a Dispatcher:** At first the Dispatcher simply wakes the PM.
3. **Convert one step:** Pick the step with the most drift and run it according to its tier (`Maker`), handing back to the PM.
4. **Add sign-off `sha256` hashes, notes records, the Pre-Escalation Gate, and `/recap`.**
5. **Convert the remaining steps** one at a time, letting each step hand over to the next bot.
6. **Drop the PM context** once the Dispatcher starts the first bot directly.

### 7.6 Trade-Offs and Open Questions (Active Brainstorming Surface)

- **Start-up latency:** Tier 2 and Tier 3 steps pay to load fresh contexts (`Maker` [+ `Cold Scouter`]). *Open question:* Can shared context be cached (e.g., prompt-prefix caching of immutable skill/charter files) without reintroducing stale session memory?
- **Deterministic Tiering (Tier 1 / Tier 2 / Tier 3):** Closed-endpoint deterministic steps (Tier 1) run without a subagent or scouter, bounded subtasks (Tier 2) run an isolated `Maker` with deterministic script/audit gates and `sha256` handoffs, and creative/open-ended tasks (Tier 3) run `Maker` + `Cold Scouter` from the start.
- **Pre-Escalation Accuracy:** Requiring `Maker` to verify derivability from `/ontological-clarity` (and run `Cold Scouter` where external prior art applies) filters out false-positive interruptions before they reach the human. A rising rate of escalations the gate should have dissolved, or of the same surprise or decision recurring at one step, signals incoherent charters or `SKILL` boundaries; fix them via `/recap` rather than loosening the rule or adding timeouts.
- **Audit trail & run-folder retention:** Run folders, notes records, `sha256` hashes, and recaps make every output traceable. Once absorbed into canonical git checkpoints in `not-a-toe` (or Extended Memory repos), transient `work/<slug>/` and `work/plan/<task-id>/` folders are pruned once their Recap is settled (§4.5), so stale trajectories do not linger.
- **External Signal Injection (`Cold Scouter`):** In Tier 3 tasks (by default) and in Tier 2 pre-escalation checks (when an external/technical question arises), a cold retiring **`Scouter`** injects external signal from inferred spaces (X, GitHub, docs, papers) to break any remaining blind spot before escalating to the human; post-run **`Recap` (`/recap`)** audits what remains.
- **Skill sprawl:** "Fix the process" adds instructions over time, so skills need regular pruning during `/recap`. Pruning is the one routine fix that does not replace a decision.

### 7.7 Glossary

- **Decision:** A choice made by the human. Bots are delegated tasks, never decisions.
- **House rule:** the `/ontological-clarity` skill, the one rule every bot loads (referred to, never restated).
- **Task Tiers (Tier 1 / Tier 2 / Tier 3):** Deterministic classification set up front in `SKILL`s: Tier 1 (closed-endpoint script/executor only), Tier 2 (bounded subtask: isolated `Maker` with deterministic gates), Tier 3 (creative/open-ended task: `Maker` + `Cold Scouter` by default).
- **Pre-Escalation Gate:** Deterministic verification before interrupting the human: `Maker` verifies derivability from `/ontological-clarity` (and if still unresolved where external prior art applies, spins up a cold `Scouter` → reconsiders) before surfacing a decision to the human.
- **Bot:** The base model with a particular charter and skills loaded (`Bot = base model + charter + skills`); a temporary context, not a separate entity.
- **Dispatcher:** The only persistent bot; holds all triggers and starts the first bot of each chain.
- **Maker:** The clone that produces a step's artifact (the task owner).
- **Cold scouter:** A single-pass context that infers the highest-signal external spaces for the task (X, GitHub, official docs, papers), writes a structured findings report, and retires immediately.
- **Sign-off:** The maker's verification of the exact final file, recorded with its `sha256`.
- **Handoff:** Transfer of a finished artifact along the **Artifact Identity Highway (`yₗ`)** via a data-free pointer (`STATUS:`) with zero chat history, official once every receiver has recomputed the `sha256` and recorded `HANDOFF_CONFIRMED`.
- **Skill Residual Block (`yₗ₊₁ = yₗ + F(yₗ, θₗ)`):** A bounded step governed by charter `θₗ` that reads the `sha256`-verified reference `yₗ` from the artifact highway and runs an isolated `Maker` + deterministic verification gates to emit a verified differential `Δyₗ = F(yₗ, θₗ)` before transient contexts drop.
- **Recap (`/recap`):** A cold post-task or operator-initiated cross-run backward pass over the run folder or session surprise against the house rule, applying surgical charter/skill updates (`Δθₗ`), **topological mitosis** (`F → F₁, F₂, …` when orthogonal axes compress under capacity overload), or **zero-context crystallization** (`Tier 3 → Tier 2 → Tier 1` when `Δθₗ → 0` across runs) per §4.5.
- **Carry-over note:** Late information passed from one run to the next, cleared once acted on.

### 8.2 Handoff Protocol with Grok Bot (Optional Bridge)
