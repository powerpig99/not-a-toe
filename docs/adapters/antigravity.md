## 3. Prior-Conditioned Layer Progression, Operational Safeguards & Adaptive Parallel Streamlines (`W`)

1. **`/sleep` (Prior-Driven Causal Ripple: `Node 0` + `Pre-Wave Sweep` + `Chain of Priors DELTA Wave Until NO_DELTA` + `Post-Wave Sweep`):**
   - **Re-trace from the current edge, never from historical traces:** Every step is a **prior-conditioned residual update (`y_target' = y_target + Δy(y_target | Prior)`)**: in Round 1 (`Node 0`, `_reverse-link-sweep`, and `L1`), the new post **`N` is the active prior (`Prior = N`)**; in subsequent layers $L_k$ ($k \ge 2$), the newly refined parent post(s) $p \in \text{DELTA}_{k-1}^{\text{propagates}}$ linked to $u \in L_k$ in $L_{k-1}$ serve as the active prior (**`Prior = p`**). `work/wave.md` is a `Dispatcher`-only single-cycle cursor (`Drafter` and `Translator` never read it) and is cleared after each cycle so prior-wave sign-offs and `NO_DELTA` rationales never accumulate as Image lag.
   - **Node `0` (`_plan-consolidation` — Stage 1 Only: `Drafter`, Zero Translation, `Prior = N`):** Uses `N` as the active prior to update `docs/wave-refinement-plan.md`, `docs/adapters/*.md`, `AGENTS.md`, `docs/charters/*.md`, and `/Users/jingliang/.grok/skills/*/SKILL.md` whenever `N`'s cut exposes an operational contradiction or procedural blind spot.
   - **Pre-Wave Reverse-Link Sweep (`_reverse-link-sweep` — Stage 1 `Drafter`, `Prior = N`):** Uses `N` as the active prior across `content/book/index-of-premises.md`, `content/book/*.md`, and the compact `slug + # Title + *Subtitle*` catalog of all posts outside `links_out(N) ∪ {N}` to propose and verify any unlinked posts `S_pre` whose claims have an obvious contradiction or logical inconsistency against `N` (needing `P -> N` or `N -> P`), merging confirmed candidates into $L_1 = (\text{links\_out}(N) \cup S_{\text{pre}}) \setminus \{N\}$.
   - **Recursive Prior-Driven `DELTA` Wave (`L1 → L2 → ...` Stopping at `NO_DELTA` — Refinement Strictly for Obvious Contradictions or Logical Inconsistencies, Never for Minor Improvements):** Runs across $L_k$ under the Prior-Conditioned Ripple Gate (`Prior = N` for $L_1$; `Prior = p@sha ∈ DELTA_{k-1}^propagates` for $k \ge 2$) under **`"非必要不变更，防止无意识漂移"`** (refinement of existing posts is aimed strictly at resolving obvious contradictions or logical inconsistencies, plus weaving a causally required reverse link in $L_1$ where the post already takes that step, or fixing a broken repository invariant; if there is no obvious contradiction or logical inconsistency, `NO_DELTA`—never refine just for minor improvements): where resolving an obvious contradiction against `Prior` changes a claim the post's other linked neighbors face—its core cut moved or the restating `links_in(<slug>)` list in `work/<slug>/notes.md` (from `node scripts/project-posts-graph.mjs --interfaces <slug>`) is non-empty (`DELTA (propagates)` → `DRAFTER: confirmed`)—it runs Stages 1–3 and expands as the active prior to the next layer; where that same `links_in(<slug>)` interface record shows none of them restating a moved claim with the core cut unchanged, or the edit weaves a direct $L_1$ reverse link / repairs self-contained local hygiene/anchor/bilingual drift (`DELTA (terminal)` → `DRAFTER: confirmed`), it runs Stages 1–3 to commit the local fix cleanly and **stops that branch without expanding into $L_k$**; where there is no obvious contradiction or logical inconsistency against `Prior` ($\Delta y(u \mid \text{Prior}) = 0$) and the target passes all invariants (`NO_DELTA` → `DRAFTER: confirmed_no_delta`), it skips Stages 2–3 and **stops that branch immediately**. Only `DELTA (propagates)` nodes expand to the next layer along reverse (`in_degree <= 30`, or where `in_degree > 30`, the members of `links_in(p)` listed in `work/<p>/notes.md` as restating the claim `p` moved) and forward links for any `(u, p@sha)` pair not yet evaluated in the wave (per `docs/wave-refinement-plan.md` §4.2 step 4) until a layer produces zero `DELTA (propagates)` or zero unevaluated `(u, p@sha)` pairs.
   - **Post-Wave Cross-Link Sweep (`_post-wave-sweep` — Stage 1 `Drafter`):** Uses `N` and all `DELTA` posts from the wave as priors against the unvisited corpus catalog to verify that no newly refined `DELTA` cut missed a cross-link, or left an unvisited post restating a claim the wave moved (checked as in step 3), before `/sleep` finishes.
2. **`/deep-sleep` (Fresh First-Time Logical Evaluation Across All Remaining Posts and Book/Site Contents via Ephemeral `batch-dispatcher` Subagents):**
   - Once `/sleep` finishes `N`'s `DELTA` ripple, `/deep-sleep` consolidates **all remaining unvisited posts (`content/posts/*.md \ visited`, ordered directly from the current living book structure by Book Part—`PART_ORDER` in `build.mjs` and the essay order in `content/book/<part>.md`, or a specific `part=<part>` if passed, with zero `git log` queries during routine sleep consolidation; past git commit history is consulted only with a strong reason, such as when the current edge is lost)** and **all remaining book/site contents (`content/book/preface.md`, `content/book/<part>.md`, `content/book/index-of-premises.md`)** in batches of size $B$ (default $B = 12$, selected deterministically via `node scripts/project-posts-graph.mjs --next-batch 12`) across $W$ parallel streamlines by **evaluating each post and book surface from the current edge as if it is being evaluated for the first time**—reading related materials as deemed necessary (`content/book/index-of-premises.md`, `content/book/<part>.md`, linked neighbors, conceptually related posts, and the newly consolidated corpus frontier) and conducting a fresh logical analysis from the irreducible prior with `/ontological-clarity` under **`"非必要不变更，防止无意识漂移"`** (`Drafter` → `Translator` → `Dispatcher/Assembler`), clearing `work/wave.md` (`rm -f work/wave.md`) on time once the cycle finishes.
   - **Outer-Loop Dynamic Batch Progression (`O(1)` Pass/Fail Returns, Zero Polling, Multi-Layer Open-Issue Escalation, & Post-Recap Log Deletion):** To keep the top-level conversation unclouded by dozens of inner-loop per-node tool turns or multi-paragraph batch tables, the Top-Level Main Agent spawns a **fresh, ephemeral `batch-dispatcher` subagent** (`EnableWriteTools=true, EnableSubagentTools=true`) for each `Deep Sleep Batch <m>` and kills it immediately upon batch completion. Inside `Batch <m>`, `batch-dispatcher` keeps its context strictly `O(1)` per node (reading only `drafter.md`, `translator.md`, and `recap.md` at startup, running `node scripts/project-posts-graph.mjs --next-batch 12`, never calling `read_file` on `work/wave.md`, `work/todo.md`, `work/<slug>/notes.md`, `content/book/index-of-premises.md`, or `docs/adapters/antigravity.md`, and never polling `manage_task` or `manage_subagents` in loops), dispatches the $W$ parallel leaf streamlines (`drafter` → `translator`, each returning only a 1-line `STATUS: PASS | FAIL | HOLD ... log=<path>`), runs Stage 3 assembly/deploy (`check-signoffs.py`, `interleave-post.py` with auto-H1 sync, `audit-post.py`, `audit-book.py`, `build.mjs`, `project-posts-graph.mjs`, `watch-deploy.sh`, and `check-signoffs.py --record-batch <m> --commit <sha>`), runs the batch's `recap` (over `work/_logs/batch-<m>.md` and the kept `work/<slug>/` folders) + §4.5 settlement, deletes settled `work/<slug>/` workspaces (`open_issues == 0`), and returns **only** a 1-line status token (`STATUS: PASS batch=<m> delta=<D> no_delta=<N> open_issues=0 remaining=<R> commit=<sha> log=work/_logs/batch-<m>.md` or `STATUS: HOLD|OPEN_ISSUES|PAUSED_FOR_WAKE ... open_issues=<K> log=work/_logs/batch-<m>.md`). In the **same top-level turn**, whenever `open_issues == 0` (`STATUS: PASS`), no `/wake` or user interrupt has arrived, and `remaining > 0`, the Top-Level Main Agent outputs a 1-line status line (`Batch <m>: PASS (delta=<D>, no_delta=<N>, remaining=<R>, commit=<sha>)`) and immediately registers (per item 1, from the current `docs/charters/batch-dispatcher.md`) and invokes a fresh `batch-dispatcher` for `Batch <m+1>` without reading `work/_logs/batch-<m>.md` (and if any long-running context ever approaches capacity, checkpoints via `/bridge` and continues via `/resume-bridge` rather than ever hitting runtime auto-compaction). Only when `open_issues > 0` are the remaining unresolved issues read on a need-to-know basis by the outer-loop `Recap` and, if still unresolved, surfaced to the Operator (whose resolution is first tested for logical consistency with `/ontological-clarity` before application). After the final outer-loop `Recap` and Operator resolution complete, `work/wave.md` is cleared and `work/_logs/` is **presented to be deleted (`rm -rf work/_logs`)** to eliminate Image lag.
3. **Customizable & Auto-Derived Concurrency ($W$ Parallel Streamlines):**
   - **Explicit Override:** If the Operator specifies a concurrency target (e.g., `/sleep concurrency=8` or `/deep-sleep 10`), the Main Agent maintains $W$ concurrent node streamlines in `work/<slug-j>/`.

## 4. Antigravity Realization of the Orthogonal Planning Cycle (`Planner` → `Scouter` → `Planner` → `Task Dispatcher`)

For any task across `not-a-toe` or any project in Extended Memory (`/Users/jingliang/Projects/*`) that requires structured external/open-internet research before execution (Section 6 of [`docs/wave-refinement-plan.md`](../wave-refinement-plan.md)), the **Main Agent** acts as the deterministic inter-agent router during Cycles $1 \dots N$ and as the **`Task Dispatcher`** once `final-plan.md` locks, orchestrating `planner` and `scouter` subagents inside `<project>/work/plan/<task-id>/`:

### 4.1 Role-to-Primitive Mapping & Uncontaminated Routing Protocol

To preserve the strict context boundary requiring `Task Dispatcher` to operate on `final-plan.md` without accumulating intermediate `research-v*.md` trajectories in its context:
- **Minimal Status Token Replies:** During Cycles $1 \dots N$, `planner` and `scouter` return **only** a single-line status token and file path (`STATUS: PLAN_READY <path>`, `STATUS: RESEARCH_READY <path>`, `STATUS: RESIDUALS_PACKAGED <path>`, `STATUS: PLANNER_CONFIRMED <path>`, or `STATUS: HOLD <path>`).
- **Pointer-Only Routing by Main Agent:** While $N \le \text{max\_cycles}$ and no `STATUS: HOLD` occurs, the Main Agent routes file paths between `planner_id` and `scouter_vN_id` **without reading `research-v*.md` into the Main Agent's context**. Only when `planner_id` returns `STATUS: PLANNER_CONFIRMED work/plan/<task-id>/final-plan.md` does the Main Agent read `final-plan.md` as `Task Dispatcher` (or, on `STATUS: HOLD` / `max_cycles`, reads `residuals-vN.md` to surface the escalation package to the Operator).

| Planning Role | Antigravity Primitive | Context Passed | Context Excluded | Lifecycle |
| :--- | :--- | :--- | :--- | :--- |
| **`Planner`** | `define_subagent(Name="planner", EnableWriteTools=true, EnableMCPTools=false)` → `invoke_subagent` (`planner_id`) | Original goal + given info + `research-vN.md`; in cycle $N > 1$, `residuals-v{N-1}.md` | `scouter`'s raw search session, other task histories, `search_web` / `read_url_content` / MCP tools | Persists across cycles $v1 \dots vN$ of one planning task; writes `residuals-vN.md` (on `SCOUT`/`HOLD`) or promotes `final-plan.md` (on `PLANNER: confirmed`), then killed via `manage_subagents(Action="kill")` |
| **`Scouter`** | `define_subagent(Name="scouter", EnableWriteTools=true, EnableMCPTools=true)` → `invoke_subagent` (`scouter_vN_id`) | Path to `work/plan/<task-id>/plan-vN.md` (and `residuals-v{N-1}.md` if $N > 1$) **only** | Original user goal/prompt, session narrative, `planner_id` trajectory, prior `scouter` sessions, prior `research-v*.md` | Single pass per cycle $N$; **immediately killed** via `manage_subagents(Action="kill")` after writing `research-vN.md` |
| **`Task Dispatcher`** | **Main Agent Session** | Locked `work/plan/<task-id>/final-plan.md` (plus minimal `STATUS:` tokens during routing) | Intermediate subagent token trajectories and `research-v*.md` (unless escalated on `HOLD` / `max_cycles`) | Enforces `max_cycles` (default `3`) and `max_depth` (default `2`), surfaces any verified `HOLD`/residual package to the Operator, deterministically dispatches the verified subtask DAG in `final-plan.md` by tier (`tier: deterministic` directly; `tier: subtask` with Antigravity `Maker` + Pre-Escalation Gate; `tier: creative` via child `Planner` → `Scouter` → `Planner` recursion), and runs `recap` at task conclusion or on Operator `/recap` call |

## 5. Antigravity Realization of the End-to-End Media Workflow (`/media <slug>`) & Grok Bot Bridge

Generic specification: [`docs/wave-refinement-plan.md` §8](../wave-refinement-plan.md). Full operating detail lives in `studio/kits/shared/library/workflow.md` and the `media` skill (`~/.grok/skills/media/SKILL.md` + `references/*.md`), backed by the deterministic checks and publishing scripts in `studio/kits/shared/checks/` and `studio/kits/shared/tools/`.

1. **End-to-end execution in `studio/runs/<slug>/` (zero critics, deterministic script gates).** `/media <slug>` runs Stages 1–4 on the Mac:
   - **Stage 1 (`--studio` / `--retry`):** Tracks NotebookLM `notebook_url` and the 6 standard Studio outputs (`deep_dive_en` Long, `deep_dive_zh` Default, `interactive_report` + `mind_map`/`flashcards`/`quiz`, `explainer_en`, `explainer_zh`, `cinematic_en`; zero infographics) in `studio/runs/<slug>/studio-state.json` via `python3 studio/kits/shared/checks/studio_state.py`. When an individual NotebookLM output fails or stalls, `/media <slug> --retry` preserves all `ready`/`downloaded` outputs untouched and deletes/re-triggers only the failed/stalled output(s).
   - **Stage 2 (Covers, manifest & copy):** Generates the 3 canonical covers (`cover-audio-3000.jpg` `3000×3000` < 500 KB, `cover-shipinhao-3x4.jpg` `1080×1440`, `cover-shipinhao-share-4x3.jpg` `1440×1080`), runs `media_manifest.py`, and drafts `drafts.md` `(a)–(d)` verified with `shorttitle.py`, `yt_upload.py --print-plan`, and `shipinhao_handoff.py`.
   - **Stage 3 (`--publish`):** Uploads videos to YouTube via API (`yt_upload.py --plan-from-drafts --go` + `--readback`), publishes audio Deep Dives to Spotify (`creators.spotify.com`, uploading `cover-audio-3000.jpg` directly on each episode) and 小宇宙 (`podcaster.xiaoyuzhoufm.com`), publishes the ZH Explainer to 微信视频号 (`channels.weixin.qq.com/platform`), publishes the EN Cinematic video to X (`x_publish.sh --live` after presenting the exact draft in chat and obtaining the Operator's release approval), and verifies the 5 platform receipts with `proof_report.py`.
   - **Stage 4 (`--embed`, Tier 1):** Writes YouTube and Spotify IDs into `data/youtube.json` and `data/spotify.json`, runs `audit-post.py`, `audit-book.py`, and `build.mjs`, commits, pushes, watches deploy (`watch-deploy.sh`), verifies live players, presents any actual run surprises for `/recap`, and cleans up working run records (`run_cleanup_plan.sh local <slug>`).
2. **Starting and stopping the Grok Bot MCP server (optional bridge).** `bash scripts/grokbot-server.sh start` (on demand; `status`, `stop` when the exchange is done; serves `http://127.0.0.1:3000/v1/mcp` with the token from `~/grokbot/.env`, never printed). `bash scripts/grokbot-msg.sh send <HANDOFF.md>` sends only the path and `sha256`; `bash scripts/grokbot-msg.sh check` reads what the Dispatcher sent since the last read (every raw response is kept in `~/grokbot/.agent-serve/messages.log`); `bash scripts/grokbot-msg.sh verify <RESULT.md> <sha256>` recomputes a returned file's hash.
3. **Messaging the Dispatcher through a handoff file.** Write the request to `studio/post/_ask-<YYYYMMDD>-<topic>/HANDOFF.md`, then call `bash scripts/grokbot-msg.sh send` carrying only the file's path and its `sha256` (`shasum -a 256`); the content travels in the file, never in the message (plan §8.2). The Dispatcher recomputes the hash before acting and replies with the path and `sha256` of a `RESULT.md` beside it, which the main session recomputes before reading.
