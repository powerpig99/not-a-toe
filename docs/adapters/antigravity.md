## 1. Mapping Generic Essay Stages to Antigravity Native Primitives & Headless Claude Cold Critics

In Antigravity, **Makers** (`drafter`, `translator`, `planner`, `scouter`, `batch-dispatcher`) are loaded on demand as ephemeral Antigravity subagents via `define_subagent` and `invoke_subagent` (retired via `manage_subagents(Action="kill")`), while **Cold Critics** (`critic`, `stylist`, `evaluator`, `recap`, and Stage 0 / Pre-Escalation / §4.5 cold critics) run via **Headless Claude Code** (`claude -p --model claude-opus-5-5 --effort medium --permission-mode bypassPermissions --add-dir <project-dir> --session-id <role-uuid> "<charter + pointer-only prompt>"`, resumed on Round 2+ within the same step via `--resume <role-uuid>`). Pairing Antigravity Makers with Headless Claude Cold Critics balances quota across providers and injects cross-model orthogonality into every `Maker` ⇄ `Cold Critic` loop (`docs/wave-refinement-plan.md` §7.6). The **Main Agent** (the active conversation session with the Operator) acts as the deterministic **`Dispatcher` & `Assembler`** (holding triggers, routing handoffs, and running deterministic checks—never acting as a standing project manager or making autonomous decisions).

> **Central Invariant & Task Tiers (`docs/wave-refinement-plan.md` §1.0–1.0.1, §4.5):** Only tasks are delegated to subagents; decisions always return to the Human Operator. Task Tiers (Tier 1 script-only, Tier 2 `Maker` ⇄ `Cold Critic`, Tier 3 `Maker` + `Cold Scouter` + `Cold Critic`), the Pre-Escalation Verification Gate, and post-task / on-demand `/recap` (settled by an implementer ⇄ headless Claude cold critic pair per §4.5) apply as defined in `wave-refinement-plan.md` §1.0.1.

Because Antigravity controls turn order directly—delivering subagent replies via reactive wakeup and headless `claude -p` replies upon command completion (zero polling loops)—neither Makers nor Cold Critics can edit files out of turn or close flags unilaterally:

## 3. Prior-Conditioned Layer Progression, Operational Safeguards & Adaptive Parallel Streamlines (`W`)

1. **`/sleep` (Prior-Driven Causal Ripple: `Node 0` + `Pre-Wave Sweep` + `Chain of Priors DELTA Wave Until NO_DELTA` + `Post-Wave Sweep`):**
   - **Re-trace from the current edge, never from historical traces:** Every step is a **prior-conditioned residual update (`y_target' = y_target + Δy(y_target | Prior)`)**: in Round 1 (`Node 0`, `_reverse-link-sweep`, and `L1`), the new post **`N` is the active prior (`Prior = N`)**; in subsequent layers $L_k$ ($k \ge 2$), the newly refined parent post(s) $p \in \text{DELTA}_{k-1}^{\text{propagates}}$ linked to $u \in L_k$ in $L_{k-1}$ serve as the active prior (**`Prior = p`**). `work/wave.md` is a `Dispatcher`-only single-cycle cursor (`Drafter` and `Critic` never read it) and is cleared after each cycle so prior-wave sign-offs and `NO_DELTA` rationales never accumulate as Image lag.
   - **Node `0` (`_plan-consolidation` — Stage 1 Only: `Drafter` ⇄ `Cold Critic`, Zero Translation, `Prior = N`):** Uses `N` as the active prior to update `docs/wave-refinement-plan.md`, `docs/adapters/*.md`, `AGENTS.md`, `docs/charters/*.md`, and `/Users/jingliang/.grok/skills/*/SKILL.md` whenever `N`'s cut introduces, sharpens, or formalizes an architectural/operational insight or exposes a procedural blind spot.
   - **Pre-Wave Reverse-Link Sweep (`_reverse-link-sweep` — Stage 1 `Drafter` ⇄ `Cold Critic`, `Prior = N`):** Uses `N` as the active prior across `content/book/index-of-premises.md`, `content/book/*.md`, and the compact `slug + # Title + *Subtitle*` catalog of all posts outside `links_out(N) ∪ {N}` to propose and cold-verify any unlinked posts `S_pre` whose cut `N` re-illuminates, sharpens, or extends (needing `P -> N` or `N -> P`), merging confirmed candidates into $L_1 = (\text{links\_out}(N) \cup S_{\text{pre}}) \setminus \{N\}$.
   - **Recursive Prior-Driven `DELTA` Wave (`L1 → L2 → ...` Stopping at `NO_DELTA`):** Runs across $L_k$ under the Prior-Conditioned Ripple Gate (`Prior = N` for $L_1$; `Prior = p ∈ DELTA_{k-1}^propagates` for $k \ge 2$): where conditioning the target post on `Prior` re-illuminates, sharpens, extends, or concretely realizes its argument or cross-link lattice and changes a claim the post's other linked neighbors face (`DELTA (propagates)` → `CRITIC: confirmed`), it runs Stages 1–3 and expands as the active prior to the next layer; where `Drafter` and `Critic` integrate `Prior` locally with the claims other neighbors face unchanged, or only repair self-contained local hygiene/anchor/bilingual drift (`DELTA (terminal)` → `CRITIC: confirmed`), it runs Stages 1–3 to commit the local refinement cleanly and **stops that branch without expanding into $L_k$**; where conditioning the target on `Prior` yields zero conceptual differential ($\Delta y(u \mid \text{Prior}) = 0$) because `Prior` moves none of the target's claims (orthogonal, or an instance its cut already holds) and the target passes all invariants (`NO_DELTA` → `CRITIC: confirmed_no_delta`), it skips Stages 2–3 and **stops that branch immediately**. Only `DELTA (propagates)` nodes expand to the next layer along reverse and forward links ($L_k = (\text{links\_in}(\text{DELTA}_{k-1}^{\text{propagates}}) \cup \text{links\_out}(\text{DELTA}_{k-1}^{\text{propagates}})) \setminus \text{visited}$, excluding mega-hubs with `in_degree > 30` from `links_in` expansion) until a layer produces zero `DELTA (propagates)`.
   - **Post-Wave Cross-Link Sweep (`_post-wave-sweep` — Stage 1 `Drafter` ⇄ `Cold Critic`):** Uses `N` and all `DELTA` posts from the wave as priors against the unvisited corpus catalog to verify that no cross-link updates were missed before `/sleep` finishes.
2. **`/deep-sleep` (Fresh First-Time Logical Evaluation Across All Remaining Posts and Book/Site Contents via Ephemeral `batch-dispatcher` Subagents):**
   - Once `/sleep` finishes `N`'s `DELTA` ripple, `/deep-sleep` consolidates **all remaining unvisited posts (`content/posts/*.md \ visited`, ordered directly from the current living book structure by Book Part—`PART_ORDER` in `build.mjs` and the essay order in `content/book/<part>.md`, or a specific `part=<part>` if passed, with zero `git log` queries during routine sleep consolidation; past git commit history is consulted only with a strong reason, such as when the current edge is lost)** and **all remaining book/site contents (`content/book/preface.md`, `content/book/<part>.md`, `content/book/index-of-premises.md`)** in batches of size $B$ (default $B = 12$) across $W$ parallel streamlines by **evaluating each post and book surface from the current edge as if it is being evaluated for the first time**—reading related materials as deemed necessary (`content/book/index-of-premises.md`, `content/book/<part>.md`, linked neighbors, conceptually related posts, and the newly consolidated corpus frontier) and conducting a fresh logical analysis from the irreducible prior with `/ontological-clarity` (`Drafter` ⇄ `Cold Critic` → `Translator` ⇄ `Stylist` → `Dispatcher/Assembler`), clearing `work/wave.md` (`rm -f work/wave.md`) on time once the cycle finishes.
   - **Outer-Loop Dynamic Batch Progression (`O(1)` Pass/Fail Returns, Multi-Layer Open-Issue Escalation, & Post-Recap Log Deletion):** To keep the top-level conversation unclouded by dozens of inner-loop per-node tool turns or multi-paragraph batch tables, the Top-Level Main Agent spawns a **fresh, ephemeral `batch-dispatcher` subagent** (`EnableWriteTools=true, EnableSubagentTools=true`) for each `Deep Sleep Batch <m>` and kills it immediately upon batch completion.
