## 1. Mapping Generic Essay Stages to Antigravity Native Primitives

In Antigravity, each **Bot** (`base model + charter + skills`) is loaded on demand as an ephemeral subagent via `define_subagent` and `invoke_subagent`, and retired by dropping its context via `manage_subagents(Action="kill")`. The **Main Agent** (the active conversation session with the Operator) acts as the deterministic **`Dispatcher` & `Assembler`** (holding triggers, routing handoffs, and running deterministic checks—never acting as a standing project manager or making autonomous decisions).

> **Central Invariant & Task Tiers (`docs/wave-refinement-plan.md` §1.0–1.0.1, §4.5):** Only tasks are delegated to subagents; decisions always return to the Human Operator. Task Tiers (Tier 1 script-only, Tier 2 `Maker` ⇄ `Cold Critic`, Tier 3 `Maker` + `Cold Scouter` + `Cold Critic`), the Pre-Escalation Verification Gate, and post-task / on-demand `/recap` (settled by an implementer ⇄ cold critic pair per §4.5) apply as defined in `wave-refinement-plan.md` §1.0.1.

## 3. Prior-Conditioned Layer Progression, Operational Safeguards & Adaptive Parallel Streamlines (`W`)

1. **`/sleep` (Prior-Driven Causal Ripple: `Node 0` + `Pre-Wave Sweep` + `Chain of Priors DELTA Wave Until NO_DELTA` + `Post-Wave Sweep`):**
   - **Re-trace from the current edge, never from historical traces:** Every step is a **prior-conditioned residual update (`y_target' = y_target + Δy(y_target | Prior)`)**: in Round 1 (`Node 0`, `_reverse-link-sweep`, and `L1`), the new post **`N` is the active prior (`Prior = N`)**; in subsequent layers $L_k$ ($k \ge 2$), the newly refined parent post(s) $p \in \text{DELTA}_{k-1}^{\text{causal}}$ linked to $u \in L_k$ in $L_{k-1}$ serve as the active prior (**`Prior = p`**). `work/wave.md` is a `Dispatcher`-only single-cycle cursor (`Drafter` and `Critic` never read it) and is cleared after each cycle so prior-wave sign-offs and `NO_DELTA` rationales never accumulate as Image lag.
   - **Node `0` (`_plan-consolidation` — Stage 1 Only: `Drafter` ⇄ `Cold Critic`, Zero Translation, `Prior = N`):** Uses `N` as the active prior to update `docs/wave-refinement-plan.md`, `docs/adapters/*.md`, `AGENTS.md`, `docs/charters/*.md`, and `/Users/jingliang/.grok/skills/*/SKILL.md` whenever `N`'s cut introduces, sharpens, or formalizes an architectural/operational insight or exposes a procedural blind spot.
   - **Pre-Wave Reverse-Link Sweep (`_reverse-link-sweep` — Stage 1 `Drafter` ⇄ `Cold Critic`, `Prior = N`):** Uses `N` as the active prior across `content/book/index-of-premises.md`, `content/book/*.md`, and the compact `slug + # Title + *Subtitle*` catalog of all posts outside `links_out(N) ∪ {N}` to propose and cold-verify any unlinked posts `S_pre` whose cut `N` re-illuminates, sharpens, or extends (needing `P -> N` or `N -> P`), merging confirmed candidates into $L_1 = (\text{links\_out}(N) \cup S_{\text{pre}}) \setminus \{N\}$.
   - **Recursive Prior-Driven `DELTA` Wave (`L1 → L2 → ...` Stopping at `NO_DELTA`):** Runs across $L_k$ under the Prior-Conditioned Ripple Gate (`Prior = N` for $L_1$; `Prior = p ∈ DELTA_{k-1}^causal` for $k \ge 2$): where conditioning the target post on `Prior` re-illuminates, sharpens, extends, or concretely realizes its argument or cross-link lattice (`DELTA (causal)` → `CRITIC: confirmed`), it runs Stages 1–3 and expands as the active prior to the next layer; where both `Drafter` and `Critic` confirm $\Delta y(u \mid \text{Prior}) = 0$ on the causal axis and only repair self-contained local hygiene/anchor/bilingual drift (`DELTA (hygiene-only; causal NO_DELTA)` → `CRITIC: confirmed`), it runs Stages 1–3 to commit the local fix cleanly and **stops that branch without expanding into $L_k$**; where conditioning the target on `Prior` yields zero conceptual differential ($\Delta y(u \mid \text{Prior}) = 0$) because `Prior` is genuinely orthogonal to the target's cut and the target passes all invariants (`NO_DELTA` → `CRITIC: confirmed_no_delta`), it skips Stages 2–3 and **stops that branch immediately**. Only `DELTA (causal)` nodes expand to the next layer along reverse and forward links ($L_k = (\text{links\_in}(\text{DELTA}_{k-1}^{\text{causal}}) \cup \text{links\_out}(\text{DELTA}_{k-1}^{\text{causal}})) \setminus \text{visited}$, excluding mega-hubs with `in_degree > 30` from `links_in` expansion) until a layer produces zero causal `DELTA`.
   - **Post-Wave Cross-Link Sweep (`_post-wave-sweep` — Stage 1 `Drafter` ⇄ `Cold Critic`):** Uses `N` and all `DELTA (causal)` posts from the wave as priors against the unvisited corpus catalog to verify that no cross-link updates were missed before `/sleep` finishes.
2. **`/deep-sleep` (Fresh First-Time Logical Evaluation Across All Remaining Posts and Book/Site Contents via Ephemeral `batch-dispatcher` Subagents):**
   - Once `/sleep` finishes `N`'s `DELTA` ripple, `/deep-sleep` consolidates **all remaining unvisited posts (`content/posts/*.md \ visited`, ordered directly from the current living book structure by Book Part—`PART_ORDER` in `build.mjs` and the essay order in `content/book/<part>.md`, or a specific `part=<part>` if passed, with zero `git log` queries during routine sleep consolidation; past git commit history is consulted only with a strong reason, such as when the current edge is lost)** and **all remaining book/site contents (`content/book/preface.md`, `content/book/<part>.md`, `content/book/index-of-premises.md`)** in batches of size $B$ (default $B = 12$) across $W$ parallel streamlines by **evaluating each post and book surface from the current edge as if it is being evaluated for the first time**—reading related materials as deemed necessary (`content/book/index-of-premises.md`, `content/book/<part>.md`, linked neighbors, conceptually related posts, and the newly consolidated corpus frontier) and conducting a fresh logical analysis from the irreducible prior with `/ontological-clarity` (`Drafter` ⇄ `Cold Critic` → `Translator` ⇄ `Stylist` → `Dispatcher/Assembler`), clearing `work/wave.md` (`rm -f work/wave.md`) on time once the cycle finishes.
   - **Outer-Loop Dynamic Batch Progression (`O(1)` Pass/Fail Returns, Multi-Layer Open-Issue Escalation, & Post-Recap Log Deletion):** To keep the top-level conversation unclouded by dozens of inner-loop per-node tool turns or multi-paragraph batch tables, the Top-Level Main Agent spawns a **fresh, ephemeral `batch-dispatcher` subagent** (`EnableWriteTools=true, EnableSubagentTools=true`) for each `Deep Sleep Batch <m>` and kills it immediately upon batch completion. Inside `Batch <m>`, `batch-dispatcher` dispatches the $W$ parallel leaf streamlines (`drafter` ⇄ `critic` → `translator` ⇄ `stylist`, each returning only a 1-line `STATUS: PASS | FAIL | HOLD ... log=<path>`), runs Stage 3 assembly/deploy, runs the batch's cold `recap` + §4.5 settlement, writes the detailed batch/recap log to `work/_logs/batch-<m>.md`, deletes settled `work/<slug>/` workspaces (`open_issues == 0`), and returns **only** a 1-line status token (`STATUS: PASS batch=<m> delta=<D> no_delta=<N> open_issues=0 remaining=<R> commit=<sha> log=work/_logs/batch-<m>.md` or `STATUS: HOLD|OPEN_ISSUES ... open_issues=<K> log=work/_logs/batch-<m>.md`). In the **same top-level turn**, whenever `open_issues == 0`, no `/wake` or user interrupt has arrived, and `remaining > 0`, the Top-Level Main Agent outputs a 1-line status line (`Batch <m>: PASS (delta=<D>, no_delta=<N>, remaining=<R>, commit=<sha>)`) and immediately invokes a fresh `batch-dispatcher` for `Batch <m+1>` without reading `work/_logs/batch-<m>.md`. Only when `open_issues > 0` are the remaining unresolved issues read on a need-to-know basis by the outer-loop `Recap` and, if still unresolved, surfaced to the Operator (whose resolution is first tested for logical consistency with `/ontological-clarity` before application). After the final outer-loop `Recap` and Operator resolution complete, `work/wave.md` is cleared and `work/_logs/` is **presented to be deleted (`rm -rf work/_logs`)** to eliminate Image lag.
3. **Customizable & Auto-Derived Concurrency ($W$ Parallel Streamlines):**

## 4. Antigravity Realization of the Orthogonal Planning Cycle (`Planner` → `Scouter` → `Evaluator` → `Task Dispatcher`)

For any task across `not-a-toe` or any project in Extended Memory (`/Users/jingliang/Projects/*`) that requires structured external/open-internet research before execution (Section 6 of [`docs/wave-refinement-plan.md`](../wave-refinement-plan.md)), the **Main Agent** acts as the deterministic inter-agent router during Cycles $1 \dots N$ and as the **`Task Dispatcher`** once `final-plan.md` locks, orchestrating three specialized subagent types inside `<project>/work/plan/<task-id>/`:

### 4.1 Role-to-Primitive Mapping & Uncontaminated Routing Protocol

To preserve the strict context boundary requiring `Task Dispatcher` to operate on `final-plan.md` without accumulating intermediate `research-v*.md` or `debate-v*.md` trajectories in its context:
- **Minimal Status Token Replies:** During Cycles $1 \dots N$, `planner`, `scouter`, and `evaluator` return **only** a single-line status token and file path in their messages to the Main Agent (`STATUS: PLAN_READY <path>`, `STATUS: RESEARCH_READY <path>`, `STATUS: DEBATE_ROUND1_OPEN <path>`, `STATUS: PLANNER_REPLIED <path>`, `STATUS: RESIDUALS_PACKAGED <path>`, `STATUS: EVALUATOR_CONFIRMED <path>`, or `STATUS: HOLD <path>`).
- **Pointer-Only Routing by Main Agent:** While $N \le \text{max\_cycles}$ and no `STATUS: HOLD` occurs, the Main Agent routes file paths between `planner_id`, `scouter_vN_id`, and `evaluator_vN_id` **without reading `research-v*.md` or `debate-v*.md` into the Main Agent's context**. Only when `evaluator_vN_id` returns `STATUS: EVALUATOR_CONFIRMED work/plan/<task-id>/final-plan.md` does the Main Agent read `final-plan.md` as `Task Dispatcher` (or, on `STATUS: HOLD` / `max_cycles`, reads `residuals-vN.md` to surface the escalation package to the Operator).
