## 1. Mapping Generic Workflow Roles to Claude Code Native Primitives

In Claude Code, each **Bot** (`base model + charter + skills`) is spawned on demand as an isolated subagent via the **`Agent` tool** (`subagent_type: "general-purpose"`, without model downgrading per `~/.claude/CLAUDE.md` *"No model switching mid-session"*). Multi-round peer debate (`Maker` ⇄ `Cold Critic` or `Planner` ⇄ `Evaluator`) routes turns back to the same subagent instance via `SendMessage(to: "<agentId>")` (carrying only a `STATUS:` line pointing to the file where the peer or Operator wrote; never messaging a subagent while it is still running), and a Bot is retired simply by dropping its `agentId` once its `sha256` handoff is confirmed. The **Main Agent** (the active Claude Code session with the Operator) acts as the deterministic **`Dispatcher` & `Assembler`**: one dispatcher level only (never spawning an intermediate node-runner or resume-runner subagent), keeping `running subagents <= W`, reporting any stalled subagent to the Operator rather than re-spawning a duplicate on the same files, and never treating harness interruption labels (`[Request interrupted by user]`) as Operator decisions unless the Operator states a decision in plain words.

> **Central Invariant & Task Tiers (`docs/wave-refinement-plan.md` §1.0–1.0.1, §4.5):** Only tasks are delegated to subagents; decisions always return to the Human Operator. Task Tiers (Tier 1 script-only, Tier 2 `Maker` ⇄ `Cold Critic`, Tier 3 `Maker` + `Cold Scouter` + `Cold Critic`), the Pre-Escalation Verification Gate, and post-task / on-demand `/recap` (settled by an implementer ⇄ cold critic pair per §4.5) apply as defined in `wave-refinement-plan.md` §1.0.1.

## 2. Subagent Charter Templates (`Agent` Prompts for `/scout`, `/recap`, and Post Roles)

When spawning any role via Claude Code's `Agent` tool:
- Have the subagent load its charter directly by file (`Read` `/Users/jingliang/Projects/not-a-toe/docs/charters/<role>.md` as its first action, or load from `.claude/agents/<role>.md` when defined), never retyping or paraphrasing the charter, sign-off line, or verdict token in the turn prompt. The turn prompt carries only the tool-word mapping (`the ontological-clarity skill` → `~/.claude/skills/ontological-clarity/SKILL.md`; `web search` / `URL fetch` → `WebSearch` / `WebFetch`; `reading the image files directly` → `Read`; `routed by the Dispatcher` → `SendMessage(to: "<agentId>")`) and pointer-level node facts (slug, layer, active `Prior` slug(s) with commits, work folder, file paths—never pre-filled sign-off hashes and never `work/wave.md`).
- Keep `running subagents <= W`, each isolated to its own working directory.
- For **`Planner` / `Evaluator` / `Drafter` / `Critic` / `Translator` / `Stylist`**, instruct the subagent **not** to call `WebSearch` or `WebFetch`; only **`Scouter`** may use `WebSearch`, `WebFetch`, and external `curl` lookups.
- Enforce **strictly 1-line `STATUS: PASS | FAIL | HOLD ... log=<path>` returns** across all child subagents so the Main Agent's context window never accumulates intermediate subagent reasoning, narrative summaries, or raw search results; all details live in disk log files read strictly on a need-to-know basis by `Recap` or on open-issue escalation.

## 3. Claude Code Realization of the Media Embed Step (`/media <slug>`)

Generic specification: [`docs/wave-refinement-plan.md` §8](../wave-refinement-plan.md). Media are produced and published on Grok Bot; the Mac-side detail lives in `studio/kits/shared/library/workflow.md` and the `media` skill. The embed step runs in the Main Agent Session with no subagents: every step is Tier 1, and the only judgment is confirming by eye (multimodal `Read`) which infographic is English and which Chinese. Messages to Grok Bot's `Dispatcher` carry only the path and `sha256` of a request at `studio/post/_ask-<YYYYMMDD>-<topic>/HANDOFF.md` (deliveries from Grok Bot use `studio/post/<NNN>-<slug>/` only), and the answer comes back as the path and `sha256` of a `RESULT.md` beside it, each recomputed by its receiver before acting (plan §8.2), over the local `grokbot` MCP server (`bash scripts/grokbot-server.sh start|status|stop`, `bash scripts/grokbot-msg.sh send|check|verify`), as [`antigravity.md`](antigravity.md) §5 states.
