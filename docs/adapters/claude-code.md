## 1. Mapping Generic Workflow Roles to Claude Code Native Primitives

In Claude Code, each **Bot** (`base model + charter + skills`) is spawned on demand as an isolated subagent via the **`Agent` tool** (`subagent_type: "general-purpose"`, without model downgrading per `~/.claude/CLAUDE.md` *"No model switching mid-session"*). Multi-cycle planning (`Planner` → `Scouter` → `Planner`) routes turns back to the same `Planner` subagent instance via `SendMessage(to: "<agentId>")` (carrying only a `STATUS:` line pointing to the file where `Scouter` or the Operator wrote; never messaging a subagent while it is still running), and a Bot is retired simply by dropping its `agentId` once its `sha256` handoff is confirmed. The **Main Agent** (the active Claude Code session with the Operator) acts as the deterministic **`Dispatcher` & `Assembler`**: one dispatcher level only (never spawning an intermediate node-runner or resume-runner subagent), keeping `running subagents <= W`, reporting any stalled subagent to the Operator rather than re-spawning a duplicate on the same files, and never treating harness interruption labels (`[Request interrupted by user]`) as Operator decisions unless the Operator states a decision in plain words.

> **Central Invariant & Task Tiers (`docs/wave-refinement-plan.md` §1.0–1.0.1, §4.5):** Only tasks are delegated to subagents; decisions always return to the Human Operator. Task Tiers (Tier 1 script-only, Tier 2 isolated `Maker` with deterministic verification gates, Tier 3 `Maker` + `Cold Scouter`), the Pre-Escalation Verification Gate, and post-task / on-demand `/recap` apply as defined in `wave-refinement-plan.md` §1.0.1.

## 2. Subagent Charter Templates (`Agent` Prompts for `/scout`, `/recap`, and Post Roles)

When spawning any role via Claude Code's `Agent` tool:
- Have the subagent load its charter directly by file (`Read` `/Users/jingliang/Projects/not-a-toe/docs/charters/<role>.md` as its first action), never retyping or paraphrasing the charter, sign-off line, or verdict token in the turn prompt. The turn prompt carries only the tool-word mapping (`the ontological-clarity skill` → `~/.claude/skills/ontological-clarity/SKILL.md`; `web search` / `URL fetch` → `WebSearch` / `WebFetch`; `reading the image files directly` → `Read`; `routed by the Dispatcher` → `SendMessage(to: "<agentId>")`) and pointer-level node facts (slug, layer, active `Prior` slug(s) with commits, work folder, file paths—never pre-filled sign-off hashes and never `work/wave.md`).
- Keep `running subagents <= W`, each isolated to its own working directory.
- For **`Planner` / `Drafter` / `Translator`**, instruct the subagent **not** to call `WebSearch`, `WebFetch`, or external `curl` lookups; external prior art enters through **`Scouter`** (`WebSearch`, `WebFetch`, and external `curl` lookups).
- Enforce **strictly 1-line `STATUS: PASS | FAIL | HOLD ... log=<path>` returns** across all child subagents so the Main Agent's context window never accumulates intermediate subagent reasoning, narrative summaries, or raw search results; all details live in disk log files read strictly on a need-to-know basis by `Recap` or on open-issue escalation.
