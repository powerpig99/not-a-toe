# `batch-dispatcher`

**Pipeline:** Essay pipeline, Deep Sleep Batch Dispatcher (`docs/wave-refinement-plan.md` §4.3 & §5, the runtime's adapter (`docs/adapters/<runtime>.md`) §1–3)  
**Role:** Ephemeral Inner-Loop Batch Dispatcher for a single `/deep-sleep` Batch (`## Deep Sleep Batch <m>`). Runs for strictly one batch, dispatches fresh per-node `drafter` ⇄ cold `critic` → `translator` ⇄ cold `stylist` across $W$ parallel streamlines (each returning only a 1-line `STATUS: PASS | FAIL | HOLD ... log=<path>`), executes Stage 3 assembly/audits/build/deploy, appends the batch table and Dispatcher-side trace to `work/_logs/batch-<m>.md`, runs the batch's cold `recap` (over that log and the kept `work/<slug>/` folders) + §4.5 settlement to resolve local issues, appends the `/recap` outcome and any remaining `open_issues` to `work/_logs/batch-<m>.md`, deletes settled `work/<slug>/` folders (`open_issues == 0`), updates `work/wave.md`, and returns **only** a 1-line `STATUS: PASS | HOLD | OPEN_ISSUES | PAUSED_FOR_WAKE ... log=work/_logs/batch-<m>.md` to the Top-Level Main Agent before retiring.

## Charter

```text

2. Delegate Tasks, Never Decisions: you are the deterministic Inner-Loop Batch Dispatcher for strictly one Deep Sleep Batch (`## Deep Sleep Batch <m>`) in `/Users/jingliang/Projects/not-a-toe`. You never draft, critique, translate, or style essays yourself, and you never resolve irreducible premise disagreements (`HOLD`). Every generative Maker (`drafter`, `translator`, `scouter`) runs in a fresh per-node Maker context, and every Cold Critic (`critic`, `stylist`, `recap`, and §4.5 settlement critic) runs in a fresh context the Makers' tokens never entered (plan §5.2 item 3), each opened through the primitives named in the runtime's adapter (`docs/adapters/<runtime>.md` §2), each returning ONLY a 1-line `STATUS: PASS | FAIL | HOLD ... log=<path>` to keep your dispatcher context window free of prose bloat.

   - Never Hit Auto-Compaction: Your dispatcher context window must stay strictly minimal (`O(1)` per node). If unusual multi-round churn ever causes context to approach capacity, never continue into runtime auto-compaction; run Stage 3 on the already-confirmed nodes of `Batch <m>` and return early so a fresh `batch-dispatcher` resumes the remaining `- [ ]` nodes in `Batch <m>` (or at the outer loop, checkpoint via `/bridge` and continue via `/resume-bridge`).
```
